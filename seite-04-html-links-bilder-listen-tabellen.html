4.1 Links

Ein Link (Hyperlink) ist das Element <a> („anchor“, Anker). Das Attribut href sagt, wohin es geht. Der Text zwischen den Tags ist das, was man anklickt. Schreib ihn so, dass man ohne Umgebung versteht, wohin er führt (nicht „hier klicken“).

4.2 Dateipfade

Ein Pfad beschreibt, wo eine Datei liegt. Angenommen, deine Seite ist meine-website/seite-04.html:

PfadBedeutung
bild.pngim selben Ordner wie die Seite
bilder/bild.pngim Unterordner bilder
../bild.pngeinen Ordner höher (.. heißt „eins nach oben“)
/bild.pngab dem Hauptverzeichnis der Domain
https://…/bild.pngabsolute Adresse im Internet

💡 Nutze für eigene Dateien relative Pfade. Dann funktioniert die Seite lokal und auf GitHub Pages gleich. Achtung: GitHub Pages unterscheidet Groß- und Kleinschreibung!

4.3 Bilder

<img> ist ein leeres Element. src ist die Bildquelle, alt ein Ersatztext. alt ist Pflicht: Er wird vorgelesen und angezeigt, wenn das Bild fehlt. width und height reservieren den Platz, damit die Seite beim Laden nicht springt.

💡 Gängige Formate: .jpg für Fotos, .png für Grafiken mit Transparenz, .svg für Logos und Icons (skalieren ohne Qualitätsverlust), .webp modern und klein.

4.6 Tabellen

Tabellen sind für tabellarische Daten da, nicht für das Layout einer Seite. Aufbau: <table> → Zeilen <tr> (table row) → Zellen <td> (table data) oder Kopfzellen <th> (table header).

4.7 Tabellen für Fortgeschrittene

  • <thead>, <tbody>, <tfoot> gliedern Kopf, Inhalt und Fuß.
  • colspan="2" lässt eine Zelle über 2 Spalten gehen, rowspan="2" über 2 Zeilen.
  • scope="col" bzw. scope="row" sagt Screenreadern, wofür eine Kopfzelle gilt.
