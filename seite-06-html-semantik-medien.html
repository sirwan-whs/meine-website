6.1 Block- und Inline-Elemente

Block-Elemente beginnen immer in einer neuen Zeile und nehmen die ganze Breite ein, z. B. p, h1–h6, ul, div, section.

Inline-Elemente stehen im Textfluss und sind nur so breit wie ihr Inhalt, z. B. a, strong, em, span, img.

Ich bin ein p (Block) und gehe über die ganze Breite.

Ich bin auch ein Block und beginne in einer neuen Zeile.

In mir stecken ein Link, ein strong und ein span. Das sind Inline-Elemente.

💡 Mit CSS kann man das ändern: display: block bzw. display: inline. Mehr dazu auf den CSS-Seiten.

6.2 div und span

<div> (Block) und <span> (Inline) haben keine eigene Bedeutung. Sie sind neutrale Behälter, die man mit CSS oder JavaScript anspricht. Nutze sie nur, wenn kein passenderes Element existiert.

6.4 Semantische Elemente

Semantisch heißt: Der Name sagt, was drinsteht. Statt überall div zu benutzen, nimmst du Elemente, die Browser, Suchmaschinen und Screenreader verstehen:

header
Kopfbereich (Logo, Titel, Navigation)
nav
Hauptnavigation mit Links
main
der Hauptinhalt, nur einmal pro Seite
section
ein Themenabschnitt, meist mit Überschrift
article
ein für sich verständlicher Inhalt, z. B. Blogartikel oder Kommentar
aside
Nebeninhalt, z. B. Seitenleiste oder Infobox
footer
Fußbereich (Impressum, Kontakt, Copyright)
time
Datum oder Uhrzeit in maschinenlesbarer Form

6.5 Auf- und zuklappen

Was ist der Unterschied zwischen Git und GitHub?

Git ist das Programm für Versionen auf deinem Rechner. GitHub ist eine Website, auf der Git-Repos gespeichert und geteilt werden.

Ist HTML eine Programmiersprache?

Nein, eine Auszeichnungssprache. Es gibt keine Variablen, Bedingungen oder Schleifen.

6.6 Audio und Video

Mit <video> und <audio> spielst du Medien ohne Zusatzprogramm ab. Mehrere <source> geben Alternativen; der Browser nimmt die erste, die er kann. Der Text dazwischen erscheint nur in sehr alten Browsern. 

<video width="640" height="360" controls poster="bilder/vorschau.jpg">
  <source src="videos/film.mp4"  type="video/mp4">
  <source src="videos/film.webm" type="video/webm">
  <track src="videos/untertitel.vtt" kind="subtitles" srclang="de" label="Deutsch">
  Dein Browser kann leider keine Videos abspielen.
</video>

<audio controls>
  <source src="audio/lied.mp3" type="audio/mpeg">
</audio>
  • controls – Play, Pause, Lautstärke anzeigen
  • autoplay – sofort starten (geht meist nur zusammen mit muted)
  • loop – endlos wiederholen
  • poster – Vorschaubild vor dem Start
  • <track> – Untertitel

💡 Leg dir einen Ordner videos an und probiere es mit einem eigenen kurzen Handy-Video (als .mp4) aus. Halte Dateien klein, GitHub erlaubt maximal 100 MB pro Datei.

6.7 Andere Seiten einbetten (iframe)

Ein <iframe> ist ein Fenster, in dem eine andere Seite angezeigt wird. So bettet man z. B. YouTube-Videos oder Karten ein (der Code dafür steht bei YouTube unter Teilen → Einbetten). title beschreibt den Inhalt für Screenreader.

6.9 Der head-Bereich

Was im <head> steht, sieht man nicht direkt, es ist aber wichtig. Schau in den Quelltext dieser Seite:

  • <meta charset="UTF-8"> – Zeichensatz für Umlaute und Emojis
  • <meta name="viewport" …> – richtige Darstellung auf dem Handy
  • <meta name="description" …> – Beschreibung für Suchmaschinen
  • <title> – Text im Browser-Tab und bei Lesezeichen
  • <link rel="stylesheet" …> – CSS-Datei einbinden
  • <link rel="icon" …> – das Favicon (schau auf diesen Tab!)
  • <script src="…"> – JavaScript einbinden (hier am Ende des body)

6.10 Barrierefreiheit

Eine gute Website kann jeder benutzen, auch mit Screenreader oder nur mit der Tastatur. Die wichtigsten Regeln:

  1. Jedes Bild hat einen sinnvollen alt-Text (reine Deko: alt="").
  2. Jedes Formularfeld hat ein label.
  3. Überschriften in der richtigen Reihenfolge (h1 → h2 → h3).
  4. Semantische Elemente statt nur div.
  5. Links haben verständliche Texte, nicht „hier“.
  6. Buttons sind echte <button>, keine anklickbaren div.
  7. Die Sprache ist angegeben: <html lang="de">.
