21.1 Synchron und asynchron

Normaler Code läuft synchron: Zeile für Zeile, jede wartet auf die vorige. Manche Dinge dauern aber (ein Timer, eine Antwort vom Server). Würde JavaScript darauf warten, wäre die Seite so lange eingefroren. Deshalb laufen sie asynchron: JavaScript startet sie, macht sofort weiter und kümmert sich um das Ergebnis, wenn es da ist.

💡 Klick auf den Button und achte auf die Reihenfolge: „3“ kommt vor „2“, obwohl die Wartezeit 0 ist. Asynchroner Code kommt immer erst dran, wenn der aktuelle Code fertig ist (Stichwort Event Loop).

21.2 setTimeout und clearTimeout

setTimeout(funktion, millisekunden) führt die Funktion einmal nach der Wartezeit aus. 1000 ms = 1 Sekunde. Der Rückgabewert ist eine Nummer, mit der man den Timer über clearTimeout(nummer) wieder abbrechen kann.

21.3 setInterval: Wiederholen

setInterval(funktion, ms) führt die Funktion immer wieder aus, bis clearInterval(nummer) sie stoppt. Typisch für Uhren, Stoppuhren und Countdowns.

Stoppuhr: 0.0 s

⚠️ Vergiss nie clearInterval. Startest du ein Intervall mehrfach, laufen mehrere gleichzeitig und die Uhr wird doppelt so schnell. Deshalb die Prüfung if (uhrNummer !== null).

21.4 Callbacks

Ein Callback ist eine Funktion, die man einer anderen Funktion übergibt, damit sie „später zurückgerufen“ wird. Du kennst das schon: addEventListener("click", callback) und setTimeout(callback, 1000).

Das Problem: Wenn mehrere Schritte nacheinander passieren sollen, rutscht der Code immer weiter nach rechts. Das nennt man Callback-Hölle. Promises lösen das.

21.5 Promises: then, catch, finally

Ein Promise („Versprechen“) ist ein Objekt für ein Ergebnis, das erst später da ist. Es hat drei Zustände:

ZustandBedeutungReaktion mit
pendingwartet noch–
fulfillederfolgreich, mit resolve(wert).then(wert => …)
rejectedfehlgeschlagen, mit reject(fehler).catch(fehler => …)

.finally() läuft in beiden Fällen, z. B. um eine Ladeanzeige auszublenden.

21.6 async und await

async/await ist eine schönere Schreibweise für Promises. Der Code sieht aus wie normaler Code von oben nach unten:

  • async function markiert eine Funktion, in der man await benutzen darf. Sie gibt selbst immer ein Promise zurück.
  • await promise wartet, bis das Promise fertig ist, und liefert den Wert. Die Seite friert dabei nicht ein.
  • Fehler fängt man mit try … catch (mehr dazu auf Seite 22).

💡 await funktioniert nur in async-Funktionen (und in Modulen, Seite 22). Vergisst du das await, bekommst du statt des Werts ein Promise { <pending> }.

21.7 Mehrere Promises: Promise.all

Mit await nacheinander dauert es so lange wie alle Schritte zusammen. Sind die Aufgaben unabhängig, startet man sie gleichzeitig:

MethodeErgebnis
Promise.all([…])wartet auf alle; ein Fehler → alles fehlgeschlagen
Promise.allSettled([…])wartet auf alle, egal ob Erfolg oder Fehler
Promise.race([…])das erste, das fertig ist (Erfolg oder Fehler)
Promise.any([…])der erste Erfolg

21.8 fetch: Daten laden

fetch(adresse) lädt Daten von einem Server und gibt ein Promise zurück. Meist sind die Daten JSON (siehe Seite 19). Das Laden passiert in zwei Schritten:

  1. const antwort = await fetch(url) – die Antwort (Status, Kopfzeilen) ist da.
  2. const daten = await antwort.json() – der Inhalt wird gelesen und in ein Objekt umgewandelt.

Dieses Beispiel lädt die Datei daten/kurse.json aus unserem eigenen Repo.

❗ fetch klappt nicht, wenn du die HTML-Datei per Doppelklick öffnest (Adresse beginnt mit file://). Der Browser verbietet das aus Sicherheitsgründen. Öffne die Seite in VS Code mit Live Server (Rechtsklick → „Open with Live Server“) oder auf GitHub Pages.

Man kann auch Daten senden. Dafür gibt man ein zweites Argument mit (dieses Beispiel ist nur zum Lesen, unser GitHub-Pages-Server nimmt nichts an): 

const antwort = await fetch("https://example.com/api/nachrichten", {
  method: "POST",                                   // GET = holen, POST = senden
  headers: { "Content-Type": "application/json" },  // wir schicken JSON
  body: JSON.stringify({ text: "Hallo!" })          // Objekt → JSON-Text
});

21.9 Fehler bei fetch behandeln

Es gibt zwei Arten von Fehlern:

  • Netzwerkfehler (kein Internet, falsche Domain): Das Promise wird rejected → catch.
  • HTTP-Fehler wie 404 (nicht gefunden) oder 500 (Serverfehler): fetch gilt trotzdem als erfolgreich! Man muss selbst antwort.ok prüfen und einen Fehler werfen.

21.10 Praxis: Kursliste aus JSON

Alles zusammen: Daten laden, Ladeanzeige zeigen, Fehler abfangen und mit dem DOM (Seite 20) eine Liste bauen. Die künstliche Pause von 600 ms zeigt die Ladeanzeige.

✍️ Übungen

  1. Baue einen Countdown von 10 bis 0 mit setInterval, der bei 0 „🚀 Start!“ zeigt und sich selbst stoppt.
  2. Schreibe eine Funktion warte(ms) selbst und nutze sie, um drei Texte im Abstand von 1 Sekunde anzuzeigen.
  3. Ergänze daten/kurse.json um einen vierten Kurs und prüfe, ob er in 21.10 erscheint.
  4. Lade mit fetch öffentliche Testdaten, z. B. von jsonplaceholder.typicode.com/users, und zeige die Namen als Liste.
  5. Teste Promise.race: Wer gewinnt zwischen warte(300) und warte(500)?
